# 0.4.5 交付验证

日期：2026-10-25。应用源提交 `56fb280`。本版补齐手动完整开场，包含 0.4.4 的首页对齐、切歌标题、编号滚动、详情布局、歌单详情、启动分流和更新器修复。之前的验证与失败记录见 [0.4.4 记录](RELEASE-0.4.4-VALIDATION.md)。

## 运行与视觉检查

- TypeScript / Vite 生产构建及 Windows `tauri build --no-bundle -- --locked` 通过。
- 启动响应性、减少动态效果、首屏加载失败恢复、设置可达性回归通过。
- 浏览器真实 WebGL 回归通过：四种窗口尺寸、三个开发版选项卡、两个歌单入口、50 首分页、滚轮逐帧标题与 SONG 滚动检查。
- Windows 发布构建原生 WebView2 回归通过：四种窗口尺寸，两个公开版选项卡，378 个滚轮采样帧，两个歌单入口及分页，托盘隐藏和恢复。
- 原生手动完整开场实际运行到白色开场的图形/文字阶段并截图，跳过后进入音乐前奏，再次跳过后回到档案架；不再仅检查空白遮罩或按钮存在。
- 采用独立测试账号、曲库目录、WebView2 配置与静音合成音频；未使用私人账号和曲库。

以上范围 `runtimeChecked=true`。macOS 安装与 UI 实机验证未执行，`runtimeChecked=false`。

## 软件内升级与安装后验证

- 从本机已安装 0.4.4 的“关于 → 检查更新”按钮发起，真实发现 0.4.5，接受下载提示；未直接注入原生安装命令。
- 首次下载响应体中断，错误显示在关于页，原安装版仍为 0.4.4。再次点击同一更新按钮后，下载、SHA-256 校验、静默覆盖安装、自动重启全部完成。
- 新进程来自安装目录并带有安装器首次启动参数；BUILD-INFO 版本为 0.4.5、源提交 `56fb280`，关于页显示“已是最新版本 V0.4.5”。
- 安装后的窗口恢复、最大化、全屏、退出全屏均重新检查；等待入场过渡结束后主标题与整体展示左边缘相同，歌单标题误差小于 1 CSS 像素。安装后首页、歌词页、关于页截图保留在当前 QA 目录。
- 最终实际安装且与 GitHub Release 一致的 Windows EXE SHA-256：`2a2fd99c552666eeee4480dfb14b91093ee9f6e98183699656657f4212c5b1cf`。
- macOS DMG SHA-256：`f9b48ad1edd15bafa791511b26289429506256404f7474158cb927360a8c26df`。两平台最终产物构建运行 `40183448983` 成功。

## 发布流程修正

发布草稿时创建标签，意外触发了旧工作流再次构建并替换同名资产。本轮最终安装、校验值和验收以上述最终产物为准；源提交及标签没有改写。工作流现已增加已有 Release 的构建跳过检查，并用拒绝覆盖既有版本的发布命令取代自动覆盖上传。手动推广仍复用已验证的构建产物。

## 证据与复现

当前本机证据：`artifacts/current-ux`、`artifacts/current-native-ux`，均在版本控制忽略范围，不把运行日志或测试配置写进公开包。

浏览器：`node scripts/check-release-ux.mjs`。Windows 原生：先关闭其他 RhineMusic，将环境变量 `RHINE_DESKTOP_EXE` 设置为待测可执行文件，再运行同一命令。原生脚本自动创建隔离账号、曲库与浏览器目录；关闭偏好仍由原生全局接口管理，托盘测试现在保存并恢复原值。本轮早期托盘测试曾将此偏好回到“每次询问”，不影响账号、曲库或播放数据。
